Java Generics

🔷 Java Generics

🕐 22/11/2025 09:09:25 👨‍💻 @rafaelsantos
📅 Introduced in: Java 5 (J2SE 5.0)
🎯 Purpose: Provide compile-time type safety and eliminate the need for explicit casts
💡 Concept: Allows classes, interfaces, and methods to operate on types as parameters

🎯 What are Generics?

Generics are a powerful Java feature that allows you to create classes, interfaces, and methods that work with types as parameters. This provides greater type safety at compile time and eliminates the need for explicit casts, making code more readable and less error-prone.

🔷

Benefits of Generics

  • ✅ Type Safety: Type errors are detected at compile time
  • ✅ Elimination of Casts: No need for explicit conversions
  • ✅ Better Readability: Clearer and more expressive code
  • ✅ Reusability: A single code can work with different types

📚 Fundamental Concepts

1. 🔤 Type Parameters

Type parameters are identifiers that represent generic types. By convention, they are named with uppercase letters:

  • E - Element (used in Collections)
  • T - Type (generic type)
  • K - Key (key in Maps)
  • V - Value (value in Maps)
  • N - Number (numbers)
  • S, U, V - Second, third, fourth types

2. 📦 Generic Classes

Example of a simple generic class:

// Generic class for a box that can store any type
public class Box<T> {
    private T content;
    
    public void setContent(T content) {
        this.content = content;
    }
    
    public T getContent() {
        return content;
    }
}

// Usage:
Box<String> stringBox = new Box<>();
stringBox.setContent("Hello, Generics!");
String text = stringBox.getContent(); // No cast needed

Box<Integer> intBox = new Box<>();
intBox.setContent(42);
Integer number = intBox.getContent(); // No cast needed

3. 🔗 Generic Interfaces

Interfaces can also be generic:

// Generic interface for comparing objects
public interface Comparator<T> {
    int compare(T a, T b);
}

// Implementation
public class StringComparator implements Comparator<String> {
    @Override
    public int compare(String a, String b) {
        return a.compareTo(b);
    }
}

4. ⚙️ Generic Methods

Methods can be generic even in non-generic classes:

public class Utilities {
    // Static generic method
    public static <T> void swap(T[] array, int i, int j) {
        T temp = array[i];
        array[i] = array[j];
        array[j] = temp;
    }
    
    // Usage:
    // String[] words = {"a", "b", "c"};
    // Utilities.swap(words, 0, 2);
}

🎭 Wildcards

Wildcards allow greater flexibility when working with generic types, especially in class hierarchies.

1. 🔵 Unbounded Wildcard (?)

Represents an unknown type:

// Accepts any type of List
public void printList(List<?> list) {
    for (Object item : list) {
        System.out.println(item);
    }
}

2. ⬆️ Upper Bounded Wildcard (? extends T)

Restricts to a type or its subtypes:

// Accepts List of Number or its subtypes (Integer, Double, etc.)
public double sum(List<? extends Number> numbers) {
    double sum = 0.0;
    for (Number num : numbers) {
        sum += num.doubleValue();
    }
    return sum;
}

3. ⬇️ Lower Bounded Wildcard (? super T)

Restricts to a type or its supertypes:

// Accepts List of Integer or its supertypes (Number, Object)
public void addNumbers(List<? super Integer> list) {
    list.add(1);
    list.add(2);
    list.add(3);
}

🔒 Bounded Type Parameters

You can restrict the types that can be used as type parameters:

// Generic class with bounded type parameter
public class Calculator<T extends Number> {
    private T number;
    
    public Calculator(T number) {
        this.number = number;
    }
    
    public double getDoubleValue() {
        return number.doubleValue();
    }
}

// Valid usage:
Calculator<Integer> intCalc = new Calculator<>(10);
Calculator<Double> doubleCalc = new Calculator<>(10.5);

// Invalid usage (does not compile):
// Calculator<String> stringCalc = new Calculator<>("10"); // Error!

🗑️ Type Erasure

Java implements generics through Type Erasure. At runtime, generic type information is removed (erased) and replaced by their bounds or Object.

⚠️ Important: Due to Type Erasure, you cannot:
  • ❌ Create arrays of generic types: new T[10]
  • ❌ Use instanceof with generic types: obj instanceof List<String>
  • ❌ Create instances of generic types: new T()
  • ❌ Use primitive types as parameters: List<int> (use List<Integer>)

💡 Practical Examples

Example 1: Generic Stack

public class Stack<T> {
    private List<T> elements = new ArrayList<>();
    
    public void push(T element) {
        elements.add(element);
    }
    
    public T pop() {
        if (elements.isEmpty()) {
            throw new IllegalStateException("Stack is empty");
        }
        return elements.remove(elements.size() - 1);
    }
    
    public boolean isEmpty() {
        return elements.isEmpty();
    }
}

// Usage:
Stack<String> stringStack = new Stack<>();
stringStack.push("First");
stringStack.push("Second");
String top = stringStack.pop(); // "Second"

Example 2: Generic Pair

public class Pair<K, V> {
    private K key;
    private V value;
    
    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }
    
    public K getKey() { return key; }
    public V getValue() { return value; }
    
    public void setKey(K key) { this.key = key; }
    public void setValue(V value) { this.value = value; }
}

// Usage:
Pair<String, Integer> pair = new Pair<>("age", 30);
String key = pair.getKey(); // "age"
Integer value = pair.getValue(); // 30

✅ Best Practices

  • ✅ Use descriptive names for type parameters (T, E, K, V)
  • ✅ Prefer wildcards when possible for greater flexibility
  • ✅ Use bounded type parameters when you need to restrict types
  • ✅ Avoid using raw types (types without generic parameters)
  • ✅ Document complex generic classes and methods well
