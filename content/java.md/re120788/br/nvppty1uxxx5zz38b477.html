🔷 Generics em Java

🕐 22/11/2025 09:09:25 👨‍💻 @rafaelsantos
📅 Introduzido em: Java 5 (J2SE 5.0)
🎯 Objetivo: Fornecer type safety em tempo de compilação e eliminar a necessidade de casts explícitos
💡 Conceito: Permite que classes, interfaces e métodos operem com tipos como parâmetros

🎯 O que são Generics?

Generics são um recurso poderoso do Java que permite criar classes, interfaces e métodos que trabalham com tipos como parâmetros. Isso proporciona maior segurança de tipos em tempo de compilação e elimina a necessidade de fazer casts explícitos, tornando o código mais legível e menos propenso a erros.

🔷

Benefícios dos Generics

  • ✅ Type Safety: Erros de tipo são detectados em tempo de compilação
  • ✅ Eliminação de Casts: Não é necessário fazer conversões explícitas
  • ✅ Melhor Legibilidade: Código mais claro e expressivo
  • ✅ Reutilização: Um único código pode trabalhar com diferentes tipos

📚 Conceitos Fundamentais

1. 🔤 Type Parameters (Parâmetros de Tipo)

Parâmetros de tipo são identificadores que representam tipos genéricos. Por convenção, são nomeados com letras maiúsculas:

  • E - Element (usado em Collections)
  • T - Type (tipo genérico)
  • K - Key (chave em Maps)
  • V - Value (valor em Maps)
  • N - Number (números)
  • S, U, V - Segundos, terceiros, quartos tipos

2. 📦 Classes Genéricas

Exemplo de uma classe genérica simples:

// Classe genérica para uma caixa que pode armazenar qualquer tipo
public class Caixa<T> {
    private T conteudo;
    
    public void setConteudo(T conteudo) {
        this.conteudo = conteudo;
    }
    
    public T getConteudo() {
        return conteudo;
    }
}

// Uso:
Caixa<String> caixaString = new Caixa<>();
caixaString.setConteudo("Olá, Generics!");
String texto = caixaString.getConteudo(); // Sem cast necessário

Caixa<Integer> caixaInt = new Caixa<>();
caixaInt.setConteudo(42);
Integer numero = caixaInt.getConteudo(); // Sem cast necessário

3. 🔗 Interfaces Genéricas

Interfaces também podem ser genéricas:

// Interface genérica para comparar objetos
public interface Comparador<T> {
    int comparar(T a, T b);
}

// Implementação
public class ComparadorString implements Comparador<String> {
    @Override
    public int comparar(String a, String b) {
        return a.compareTo(b);
    }
}

4. ⚙️ Métodos Genéricos

Métodos podem ser genéricos mesmo em classes não-genéricas:

public class Utilidades {
    // Método genérico estático
    public static <T> void trocar(T[] array, int i, int j) {
        T temp = array[i];
        array[i] = array[j];
        array[j] = temp;
    }
    
    // Uso:
    // String[] palavras = {"a", "b", "c"};
    // Utilidades.trocar(palavras, 0, 2);
}

🎭 Wildcards (Curingas)

Wildcards permitem maior flexibilidade ao trabalhar com tipos genéricos, especialmente em hierarquias de classes.

1. 🔵 Unbounded Wildcard (?)

Representa um tipo desconhecido:

// Aceita qualquer tipo de List
public void imprimirLista(List<?> lista) {
    for (Object item : lista) {
        System.out.println(item);
    }
}

2. ⬆️ Upper Bounded Wildcard (? extends T)

Restringe a um tipo ou seus subtipos:

// Aceita List de Number ou seus subtipos (Integer, Double, etc.)
public double somar(List<? extends Number> numeros) {
    double soma = 0.0;
    for (Number num : numeros) {
        soma += num.doubleValue();
    }
    return soma;
}

3. ⬇️ Lower Bounded Wildcard (? super T)

Restringe a um tipo ou seus supertipos:

// Aceita List de Integer ou seus supertipos (Number, Object)
public void adicionarNumeros(List<? super Integer> lista) {
    lista.add(1);
    lista.add(2);
    lista.add(3);
}

🔒 Bounded Type Parameters

Você pode restringir os tipos que podem ser usados como parâmetros de tipo:

// Classe genérica com bounded type parameter
public class Calculadora<T extends Number> {
    private T numero;
    
    public Calculadora(T numero) {
        this.numero = numero;
    }
    
    public double obterValorDouble() {
        return numero.doubleValue();
    }
}

// Uso válido:
Calculadora<Integer> calcInt = new Calculadora<>(10);
Calculadora<Double> calcDouble = new Calculadora<>(10.5);

// Uso inválido (não compila):
// Calculadora<String> calcString = new Calculadora<>("10"); // Erro!

🗑️ Type Erasure

O Java implementa generics através de Type Erasure. Em tempo de execução, as informações de tipo genérico são removidas (erased) e substituídas por seus limites ou Object.

⚠️ Importante: Devido ao Type Erasure, você não pode:
  • ❌ Criar arrays de tipos genéricos: new T[10]
  • ❌ Usar instanceof com tipos genéricos: obj instanceof List<String>
  • ❌ Criar instâncias de tipos genéricos: new T()
  • ❌ Usar tipos primitivos como parâmetros: List<int> (use List<Integer>)

💡 Exemplos Práticos

Exemplo 1: Stack Genérico

public class Pilha<T> {
    private List<T> elementos = new ArrayList<>();
    
    public void empilhar(T elemento) {
        elementos.add(elemento);
    }
    
    public T desempilhar() {
        if (elementos.isEmpty()) {
            throw new IllegalStateException("Pilha vazia");
        }
        return elementos.remove(elementos.size() - 1);
    }
    
    public boolean estaVazia() {
        return elementos.isEmpty();
    }
}

// Uso:
Pilha<String> pilhaString = new Pilha<>();
pilhaString.empilhar("Primeiro");
pilhaString.empilhar("Segundo");
String topo = pilhaString.desempilhar(); // "Segundo"

Exemplo 2: Par Genérico

public class Par<K, V> {
    private K chave;
    private V valor;
    
    public Par(K chave, V valor) {
        this.chave = chave;
        this.valor = valor;
    }
    
    public K getChave() { return chave; }
    public V getValor() { return valor; }
    
    public void setChave(K chave) { this.chave = chave; }
    public void setValor(V valor) { this.valor = valor; }
}

// Uso:
Par<String, Integer> par = new Par<>("idade", 30);
String chave = par.getChave(); // "idade"
Integer valor = par.getValor(); // 30

✅ Boas Práticas

  • ✅ Use nomes descritivos para type parameters (T, E, K, V)
  • ✅ Prefira wildcards quando possível para maior flexibilidade
  • ✅ Use bounded type parameters quando precisar restringir tipos
  • ✅ Evite usar raw types (tipos sem parâmetros genéricos)
  • ✅ Documente bem classes e métodos genéricos complexos
