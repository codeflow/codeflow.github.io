🟢 📚 Overview

Operating system architecture defines how the OS is structured internally, how components interact, and how the system provides services to applications. Understanding OS architecture is fundamental to comprehending how modern operating systems work.

🟡 📚 Kernel Space vs User Space

Modern operating systems divide memory into two distinct regions: kernel space and user space. This separation is crucial for system stability and security.

🟢 Kernel Space

Kernel space is the protected memory area where the operating system kernel runs. It has privileged access to hardware and system resources.

Characteristics:

  • Privileged Mode: Runs in supervisor/kernel mode with full hardware access
  • Protected Memory: User applications cannot directly access kernel space
  • Critical Components: Contains kernel code, device drivers, interrupt handlers
  • System Stability: Bugs in kernel space can crash the entire system
  • Direct Hardware Access: Can directly interact with CPU, memory, I/O devices

The kernel space is where the core operating system functions execute, including process management, memory management, file system operations, and device driver code.

🟢 User Space

User space is the memory area where user applications and most system services run. It operates in unprivileged mode with restricted access to hardware.

Characteristics:

  • Unprivileged Mode: Runs in user mode with limited hardware access
  • Isolated Memory: Each process has its own protected memory space
  • Application Code: Contains user applications, libraries, system services
  • System Calls Required: Must use system calls to access kernel services
  • Process Isolation: Processes cannot directly access each other's memory

User space applications must request kernel services through system calls, which provide a controlled interface to kernel functionality.

🟡 📚 System Calls

System calls are the interface between user space applications and the kernel. They allow applications to request services from the operating system in a controlled and secure manner.

How System Calls Work:

  1. Application Request: User program calls a library function (e.g., read(), write())
  2. Library Wrapper: Library function prepares parameters and invokes the system call
  3. Mode Switch: CPU switches from user mode to kernel mode (trap/interrupt)
  4. Kernel Execution: Kernel validates the request and performs the operation
  5. Return to User Mode: Kernel returns result and switches back to user mode
  6. Application Continues: Library function returns result to the application

🟡 🛠️ System Call Examples

The following examples demonstrate common system calls used in Unix/Linux systems:

C 
#include <unistd.h>
#include <sys/types.h>
#include <fcntl.h>
#include <stdio.h>

int main() {
    // File Management System Calls
    int fd = open("example.txt", O_RDONLY);
    if (fd == -1) {
        perror("open");
        return 1;
    }
    
    char buffer[1024];
    ssize_t bytes_read = read(fd, buffer, sizeof(buffer) - 1);
    if (bytes_read == -1) {
        perror("read");
        close(fd);
        return 1;
    }
    
    buffer[bytes_read] = '\0';
    printf("Read %zd bytes: %s\n", bytes_read, buffer);
    
    close(fd);
    
    // Process Control System Calls
    pid_t pid = getpid();
    pid_t ppid = getppid();
    printf("Process ID: %d\n", pid);
    printf("Parent Process ID: %d\n", ppid);
    
    return 0;
}

Part 1: File Management System Calls

The open() system call opens a file and returns a file descriptor. O_RDONLY specifies read-only mode. If the call fails, it returns -1 and sets errno to indicate the error. perror() prints a descriptive error message.

Part 2: Reading from File

C 
char buffer[1024];
ssize_t bytes_read = read(fd, buffer, sizeof(buffer) - 1);
if (bytes_read == -1) {
    perror("read");
    close(fd);
    return 1;
}

The read() system call reads data from the file descriptor into the buffer. It returns the number of bytes read, or -1 on error. The buffer size is reduced by 1 to leave space for the null terminator.

Part 3: Process Information System Calls

C 
pid_t pid = getpid();
pid_t ppid = getppid();
printf("Process ID: %d\n", pid);
printf("Parent Process ID: %d\n", ppid);

getpid() returns the process ID of the calling process, while getppid() returns the parent process ID. These system calls are commonly used for process identification and hierarchy management.

Common System Call Categories:

  • Process Control: fork(), exec(), exit(), wait()
  • File Management: open(), read(), write(), close()
  • Device Management: ioctl(), read(), write()
  • Information Maintenance: getpid(), gettimeofday(), sysinfo()
  • Communication: pipe(), shmget(), msgget()

System calls provide a secure, controlled way for applications to access kernel services without directly accessing kernel memory or hardware.

🟡 📚 Libraries

Libraries are collections of precompiled functions that provide common functionality to applications. They serve as an abstraction layer between applications and system calls.

Types of Libraries:

  • Static Libraries: Linked at compile time, code included in executable
  • Dynamic/Shared Libraries: Linked at runtime, shared among multiple processes
  • System Libraries: Provided by the OS (e.g., libc, libm)
  • Application Libraries: Third-party or application-specific libraries

Standard C Library (libc):

  • Provides wrapper functions for system calls
  • Offers higher-level abstractions (e.g., printf(), malloc())
  • Handles error checking and parameter validation
  • Provides portable interface across different systems

Libraries simplify application development by providing reusable, well-tested functions and abstracting away low-level system call details.

🟡 📚 Device Drivers

Device drivers are kernel modules that provide an interface between the operating system and hardware devices. They translate generic OS requests into device-specific commands.

Driver Functions:

  • Hardware Abstraction: Hide device-specific details from the OS
  • Device Initialization: Configure and initialize hardware devices
  • I/O Operations: Handle read/write operations to devices
  • Interrupt Handling: Process hardware interrupts from devices
  • Error Handling: Detect and handle device errors

Driver Types:

  • Character Drivers: Handle character-by-character I/O (keyboards, serial ports)
  • Block Drivers: Handle block-based I/O (hard disks, SSDs)
  • Network Drivers: Handle network interface cards
  • USB Drivers: Handle USB devices

Drivers run in kernel space and have direct access to hardware, making them critical for system functionality and potential points of failure.

🟡 📚 Operating System Layers

Operating systems are typically organized in layers, with each layer providing services to the layer above and using services from the layer below.

Typical OS Layer Structure:

  1. Hardware Layer: Physical components (CPU, memory, I/O devices)
  2. Kernel Layer: Core OS functions (process management, memory management, I/O management)
  3. System Call Interface: Interface between user space and kernel
  4. Libraries Layer: System libraries (libc, libm, etc.)
  5. Application Layer: User applications and programs

Benefits of Layered Architecture:

  • Modularity: Each layer has a well-defined interface
  • Maintainability: Changes in one layer don't affect others
  • Portability: Upper layers can be ported to different hardware
  • Abstraction: Higher layers don't need to know lower layer details
  • Security: Controlled interfaces between layers

🟡 📚 Memory Protection and Privilege Levels

Modern CPUs provide hardware support for memory protection and privilege levels, which operating systems use to enforce the kernel/user space separation.

Privilege Rings (x86 Architecture):

Ring 3 (User Mode)

Memory Protection Mechanisms:

  • Memory Management Unit (MMU): Translates virtual addresses to physical addresses
  • Page Tables: Define which memory pages are accessible and with what permissions
  • Segmentation: Divides memory into segments with different access rights
  • Access Control Bits: Read, write, execute permissions for memory pages

These hardware mechanisms ensure that user applications cannot access kernel memory or interfere with system operation.

🟡 📚 Interrupts and Exceptions

Interrupts and exceptions are mechanisms that allow the CPU to handle asynchronous events and errors, enabling the OS to respond to hardware events and system errors.

Types of Interrupts:

  • Hardware Interrupts: Generated by hardware devices (keyboard, network card, timer)
  • Software Interrupts: Generated by software (system calls, exceptions)
  • Exceptions: Generated by CPU for errors (division by zero, page fault, invalid instruction)

Interrupt Handling Process:

  1. CPU receives interrupt signal
  2. CPU saves current context (registers, program counter)
  3. CPU switches to kernel mode
  4. Kernel interrupt handler executes
  5. Handler processes the interrupt
  6. CPU restores saved context
  7. CPU returns to interrupted code

Interrupts are essential for responsive systems, allowing the OS to handle I/O completion, timer events, and errors without polling.

🟡 📚 Process and Thread Management

The operating system manages processes and threads, providing the abstraction of concurrent execution.

Process Management:

  • Process Creation: fork(), exec() system calls
  • Process Scheduling: CPU time allocation among processes
  • Context Switching: Saving and restoring process state
  • Process Termination: Cleanup and resource deallocation

Thread Management:

  • Thread Creation: Lightweight processes sharing address space
  • Thread Synchronization: Mutexes, semaphores, condition variables
  • Thread Scheduling: User-level and kernel-level threads

Process and thread management is a core kernel function, requiring careful coordination to ensure fairness, responsiveness, and correctness.

🟡 📚 File System Architecture

The file system provides persistent storage abstraction, organizing data into files and directories.

File System Components:

  • File System Interface: System calls for file operations (open(), read(), write())
  • Virtual File System (VFS): Abstraction layer for different file system types
  • File System Implementation: Specific file system code (ext4, NTFS, FAT32)
  • Block Device Layer: Interface to storage devices
  • Device Drivers: Hardware-specific storage drivers

The VFS allows the OS to support multiple file system types simultaneously, providing a unified interface to applications.
