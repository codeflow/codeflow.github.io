⚙️ Process Creation and Termination

🕐 2026-02-20 👨‍💻 @rafaelsantos
📚 About: Process creation and termination are fundamental operations in operating systems. This topic covers system calls like fork(), exec(), wait(), and exit(), process hierarchy, and special process states like zombie and orphan processes.

🟢 📚 Process Creation Basics

Process creation is the mechanism by which new processes are spawned in an operating system. In Unix-like systems, the primary method for creating new processes is through the fork() system call.

When a process calls fork(), the operating system creates an exact copy of the calling process. This new process is called the child process, while the original process is called the parent process.

Key Characteristics of fork():
  • Creates an exact duplicate of the parent process
  • Child process gets a copy of parent's memory space
  • Both processes continue execution from the point after fork()
  • Returns different values: 0 in child, child's PID in parent
  • Child process gets a unique Process ID (PID)

🟢 🛠️ Basic fork() Example

Here's a simple example demonstrating process creation with fork():

C 
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main() {
    pid_t pid;
    
    printf("Before fork()\n");
    
    pid = fork();
    
    if (pid == 0) {
        // Child process
        printf("Child process: PID = %d\n", getpid());
        printf("Child: Parent PID = %d\n", getppid());
    } else if (pid > 0) {
        // Parent process
        printf("Parent process: PID = %d\n", getpid());
        printf("Parent: Child PID = %d\n", pid);
    } else {
        // fork() failed
        perror("fork");
        return 1;
    }
    
    printf("After fork() - both processes execute this\n");
    return 0;
}

Process ID Variables

pid_t is a data type used to represent process IDs. It's typically defined as an integer type that can hold a process identifier.

Fork System Call

C 
pid = fork();

The fork() system call creates a new process by duplicating the calling process. It returns:

  • 0 in the child process
  • Child's PID in the parent process (a positive number)
  • -1 on error

Process Identification

C 
if (pid == 0) {
    // Child process
    printf("Child process: PID = %d\n", getpid());
    printf("Child: Parent PID = %d\n", getppid());
} else if (pid > 0) {
    // Parent process
    printf("Parent process: PID = %d\n", getpid());
    printf("Parent: Child PID = %d\n", pid);
}

getpid() returns the current process's PID, while getppid() returns the parent process's PID. The child process uses the return value of fork() (0) to identify itself, while the parent uses the returned PID to track its child.

🟡 📚 Process Hierarchy

Processes in Unix-like systems form a hierarchical tree structure. Every process (except the init process with PID 1) has a parent process. This creates a process tree where:

  • The init process (PID 1) is the root of the process tree
  • Each process can create child processes using fork()
  • Child processes can create their own children, forming a tree structure
  • When a parent terminates, its children become orphan processes
  • ⚙️ init (PID 1)
    • 💻 shell (PID 100)
      • 📄 process_a (PID 200)
        • 📄 process_b (PID 201)
      • 📄 process_c (PID 202)
    • 🔧 daemon (PID 101)

🟡 🛠️ Creating Multiple Child Processes

This example demonstrates creating multiple child processes and managing the process hierarchy:

C 
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main() {
    pid_t pid1, pid2, pid3;
    int i;
    
    printf("Parent PID: %d\n", getpid());
    
    // Create first child
    pid1 = fork();
    if (pid1 == 0) {
        printf("Child 1: PID = %d, Parent PID = %d\n", getpid(), getppid());
        sleep(2);
        exit(0);
    }
    
    // Create second child
    pid2 = fork();
    if (pid2 == 0) {
        printf("Child 2: PID = %d, Parent PID = %d\n", getpid(), getppid());
        sleep(2);
        exit(0);
    }
    
    // Create third child
    pid3 = fork();
    if (pid3 == 0) {
        printf("Child 3: PID = %d, Parent PID = %d\n", getpid(), getppid());
        sleep(2);
        exit(0);
    }
    
    // Parent waits for all children
    for (i = 0; i < 3; i++) {
        wait(NULL);
    }
    
    printf("Parent: All children terminated\n");
    return 0;
}

🟡 📚 exec() Family of Functions

The exec() family of functions replaces the current process image with a new program. Unlike fork(), which creates a copy, exec() completely replaces the process's memory space with a new program.

Common exec() Functions:
  • execl() - Takes arguments as a list
  • execv() - Takes arguments as an array
  • execle() - With environment variables (list)
  • execve() - With environment variables (array)
  • execlp() - Searches PATH (list)
  • execvp() - Searches PATH (array)

🟡 🛠️ Using fork() and exec() Together

The common pattern is to use fork() to create a new process, then use exec() in the child to run a different program:

C 
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main() {
    pid_t pid;
    
    pid = fork();
    
    if (pid == 0) {
        // Child process: execute a new program
        printf("Child: About to execute ls command\n");
        execl("/bin/ls", "ls", "-l", NULL);
        
        // This line will never execute if execl succeeds
        perror("execl failed");
        exit(1);
    } else if (pid > 0) {
        // Parent process: wait for child to complete
        printf("Parent: Waiting for child to finish\n");
        wait(NULL);
        printf("Parent: Child process completed\n");
    } else {
        perror("fork failed");
        return 1;
    }
    
    return 0;
}

Code Breakdown

Executing a New Program

C 
execl("/bin/ls", "ls", "-l", NULL);

execl() replaces the current process image with the program specified by the first argument. The subsequent arguments are passed as command-line arguments to the new program. The last argument must be NULL to indicate the end of arguments. If execl() succeeds, it never returns because the process image is completely replaced.

Parent Waiting for Child

C 
wait(NULL);

The wait() system call suspends execution of the parent process until one of its children terminates. NULL means we don't need the exit status. The parent process blocks until the child completes execution.

🟡 📚 wait() and waitpid()

The wait() and waitpid() system calls allow a parent process to wait for its child processes to terminate and retrieve their exit status.

Key Differences:
  • wait() - Waits for any child process to terminate
  • waitpid() - Waits for a specific child process (by PID)
  • Both can retrieve exit status information
  • Both prevent zombie processes from accumulating

🟡 🛠️ Using wait() to Get Exit Status

This example shows how to retrieve the exit status of a child process:

C 
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <stdlib.h>

int main() {
    pid_t pid;
    int status;
    
    pid = fork();
    
    if (pid == 0) {
        // Child process
        printf("Child: PID = %d\n", getpid());
        printf("Child: Exiting with status 42\n");
        exit(42);
    } else if (pid > 0) {
        // Parent process
        printf("Parent: Waiting for child (PID %d) to terminate\n", pid);
        wait(&status);
        
        if (WIFEXITED(status)) {
            printf("Parent: Child exited normally with status: %d\n", WEXITSTATUS(status));
        } else if (WIFSIGNALED(status)) {
            printf("Parent: Child terminated by signal: %d\n", WTERMSIG(status));
        }
    } else {
        perror("fork failed");
        return 1;
    }
    
    return 0;
}

Code Breakdown

Retrieving Exit Status

C 
int status;
wait(&status);

By passing a pointer to an integer to wait(), we can retrieve information about how the child process terminated. The status value contains encoded information about the child's termination.

Checking Exit Status

C 
if (WIFEXITED(status)) {
    printf("Child exited normally with status: %d\n", WEXITSTATUS(status));
} else if (WIFSIGNALED(status)) {
    printf("Child terminated by signal: %d\n", WTERMSIG(status));
}

WIFEXITED(status) checks if the child exited normally. WEXITSTATUS(status) extracts the exit code. WIFSIGNALED(status) checks if the child was terminated by a signal, and WTERMSIG(status) gets the signal number.

🟡 📚 exit() and Process Termination

Processes terminate in several ways:

  • Normal termination - Process calls exit() or returns from main()
  • Abnormal termination - Process receives a signal that causes termination
  • Error termination - Process encounters an error and calls exit() with non-zero status
C 
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main() {
    printf("Process starting\n");
    
    // Normal termination with exit code 0 (success)
    exit(0);
    
    // This line never executes
    printf("This will never print\n");
}

🔴 📚 Zombie Processes

A zombie process is a process that has completed execution but still has an entry in the process table. This happens when:

  • The child process terminates
  • The parent process hasn't called wait() or waitpid() yet
  • The child's exit status is still needed by the parent
Zombie Process Characteristics:
  • Process has finished execution
  • Still occupies a slot in the process table
  • Consumes minimal system resources (just the process table entry)
  • Cannot be killed (already dead)
  • Removed when parent calls wait() or parent terminates

🔴 🛠️ Creating a Zombie Process

This example demonstrates how a zombie process is created:

C 
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <stdlib.h>

int main() {
    pid_t pid;
    
    pid = fork();
    
    if (pid == 0) {
        // Child process terminates immediately
        printf("Child: PID = %d, exiting now\n", getpid());
        exit(0);
    } else if (pid > 0) {
        // Parent process doesn't wait for child
        printf("Parent: PID = %d, Child PID = %d\n", getpid(), pid);
        printf("Parent: Not calling wait() - child will become zombie\n");
        printf("Parent: Sleeping for 30 seconds - check 'ps aux | grep defunct'\n");
        sleep(30);
        // Now wait for child (zombie will be cleaned up)
        wait(NULL);
        printf("Parent: Child cleaned up\n");
    } else {
        perror("fork failed");
        return 1;
    }
    
    return 0;
}

While the parent is sleeping, the child process becomes a zombie. You can verify this by running ps aux | grep defunct in another terminal. The zombie will be cleaned up when the parent calls wait().

🔴 📚 Orphan Processes

An orphan process is a process whose parent has terminated. When a parent process dies before its child:

  • The child process becomes an orphan
  • The init process (PID 1) becomes the new parent
  • Orphan processes are automatically adopted by init
  • Init periodically calls wait() to clean up orphaned zombies
Orphan Process Lifecycle:
1. Parent creates child process
2. Parent terminates before child
3. Child becomes orphan (parent PID changes to 1)
4. Init process adopts the orphan
5. When orphan terminates, init cleans it up

🔴 🛠️ Creating an Orphan Process

This example demonstrates how an orphan process is created:

C 
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <stdlib.h>

int main() {
    pid_t pid;
    
    pid = fork();
    
    if (pid == 0) {
        // Child process
        printf("Child: PID = %d, Parent PID = %d\n", getpid(), getppid());
        printf("Child: Sleeping for 5 seconds\n");
        sleep(5);
        printf("Child: After sleep, Parent PID = %d\n", getppid());
        printf("Child: If parent PID is now 1, I became an orphan\n");
        exit(0);
    } else if (pid > 0) {
        // Parent process terminates immediately
        printf("Parent: PID = %d, Child PID = %d\n", getpid(), pid);
        printf("Parent: Terminating now - child will become orphan\n");
        exit(0);
    } else {
        perror("fork failed");
        return 1;
    }
}

When you run this program, the parent terminates immediately while the child continues running. The child's parent PID will change from the original parent's PID to 1 (init), indicating it has become an orphan.

🔴 📚 Process Termination Best Practices

To avoid zombie processes and properly manage process lifecycle:

Best Practices:
  • Always call wait() or waitpid() for child processes
  • Use signal handlers to handle child termination (SIGCHLD)
  • Set up proper cleanup routines for process termination
  • Use exit() with appropriate exit codes (0 for success, non-zero for errors)
  • Consider using waitpid() with WNOHANG for non-blocking waits

🔴 🛠️ Handling Child Termination with Signals

This example shows how to handle child termination using the SIGCHLD signal:

C 
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <signal.h>
#include <stdlib.h>

void sigchld_handler(int sig) {
    pid_t pid;
    int status;
    
    // Wait for all terminated children (non-blocking)
    while ((pid = waitpid(-1, &status, WNOHANG)) > 0) {
        if (WIFEXITED(status)) {
            printf("Child %d exited with status %d\n", pid, WEXITSTATUS(status));
        }
    }
}

int main() {
    pid_t pid;
    struct sigaction sa;
    
    // Set up SIGCHLD handler
    sa.sa_handler = sigchld_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART | SA_NOCLDSTOP;
    sigaction(SIGCHLD, &sa, NULL);
    
    // Create child process
    pid = fork();
    
    if (pid == 0) {
        // Child process
        printf("Child: PID = %d, running for 3 seconds\n", getpid());
        sleep(3);
        exit(42);
    } else if (pid > 0) {
        // Parent process
        printf("Parent: PID = %d, waiting for child signal\n", getpid());
        // Parent continues doing other work
        while (1) {
            sleep(1);
            printf("Parent: Still running...\n");
        }
    } else {
        perror("fork failed");
        return 1;
    }
    
    return 0;
}

Code Breakdown

Signal Handler Setup

C 
struct sigaction sa;
sa.sa_handler = sigchld_handler;
sigemptyset(&sa.sa_mask);
sa.sa_flags = SA_RESTART | SA_NOCLDSTOP;
sigaction(SIGCHLD, &sa, NULL);

This sets up a signal handler for SIGCHLD, which is sent to a parent process when a child terminates. SA_RESTART ensures system calls are restarted after the signal handler, and SA_NOCLDSTOP means the signal is only sent on termination, not on stop/continue.

Non-blocking Wait

C 
while ((pid = waitpid(-1, &status, WNOHANG)) > 0) {
    // Process terminated child
}

waitpid(-1, &status, WNOHANG) waits for any child process (-1) but returns immediately if no child has terminated (WNOHANG). The loop processes all terminated children without blocking the parent process.
