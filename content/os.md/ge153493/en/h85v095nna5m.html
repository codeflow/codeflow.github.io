🔄 States and Lifecycle

🕐 18/02/2026 22:30:00 👨‍💻 @rafaelsantos
📚 About: Process states represent the different stages a process goes through during its execution. Understanding state transitions is fundamental to process management in operating systems.

📊 Process States

A process can be in one of several states during its lifecycle. The main states are:

New

The process is being created. At this stage, the operating system is allocating resources and initializing the Process Control Block (PCB).

Ready

The process is loaded into main memory and is waiting to be assigned to a CPU. It has all the resources it needs except for CPU time.

Running

The process is currently being executed by the CPU. Instructions are being executed, and the process is actively using processor resources.

Waiting (Blocked)

The process is waiting for some event to occur, such as:

  • I/O operation completion
  • Signal from another process
  • Resource availability
  • Timer expiration

Terminated

The process has finished execution or has been terminated. The operating system deallocates resources and removes the process from the system.

🔄 State Transitions

Processes transition between states based on various events:

New → Ready

When the operating system finishes creating the process and loads it into memory, it moves to the ready state.

Ready → Running

The scheduler selects the process from the ready queue and assigns it to a CPU. This transition is called dispatch.

Running → Ready

This occurs when:

  • The process's time slice expires (time quantum)
  • A higher priority process becomes ready (preemption)
  • The scheduler decides to switch processes

Running → Waiting

The process voluntarily gives up the CPU because it needs to wait for:

  • I/O operation to complete
  • Resource to become available
  • Signal or event

Waiting → Ready

When the event the process was waiting for occurs (e.g., I/O completes), the process moves back to the ready state.

Running → Terminated

The process finishes execution normally or is terminated by the operating system or another process.

💻 Practical Example

The following complete example demonstrates how to check and monitor process states in Linux:

bash 
#!/bin/bash

# Check process state using ps command
ps aux | grep process_name

# View detailed process information
ps -o pid,state,cmd -p <PID>

# Monitor process state changes in real-time
watch -n 1 'ps -o pid,state,cmd -p <PID>'

# List all processes with their states
ps -eo pid,state,cmd | head -20

# Common states in ps output:
# R - Running or Runnable
# S - Interruptible Sleep (waiting)
# D - Uninterruptible Sleep (I/O)
# T - Stopped
# Z - Zombie

Part 1: Basic Process State Check

bash 
# Check process state using ps command
ps aux | grep process_name

The ps aux command lists all running processes with detailed information. The grep command filters the output to show only processes matching the specified name. This is useful for finding a specific process and checking its current state.

Part 2: Detailed Process Information

bash 
# View detailed process information
ps -o pid,state,cmd -p <PID>

The ps -o command allows you to specify custom output formats. Here, we display the Process ID (PID), current state, and command. The -p option specifies the process ID to query. This provides precise information about a specific process's state.

Part 3: Real-time State Monitoring

bash 
# Monitor process state changes in real-time
watch -n 1 'ps -o pid,state,cmd -p <PID>'

The watch command executes the specified command repeatedly at regular intervals (every 1 second in this case). This allows you to observe state transitions in real-time, which is particularly useful for debugging and understanding process behavior.

Part 4: Understanding State Codes

The ps command uses single-letter codes to represent process states:

  • R (Running/Runnable): The process is either currently executing or ready to run
  • S (Interruptible Sleep): The process is waiting for an event (can be interrupted by signals)
  • D (Uninterruptible Sleep): The process is waiting for I/O completion (cannot be interrupted)
  • T (Stopped): The process has been stopped by a signal (e.g., SIGSTOP)
  • Z (Zombie): The process has terminated but its parent hasn't read its exit status

🔍 State Information in Process Control Block

The Process Control Block (PCB) stores the current state of the process. This information is crucial for:

  • Context Switching: The OS needs to know the process state to save and restore context
  • Scheduling: Only ready processes can be scheduled
  • Resource Management: Waiting processes indicate resource dependencies
  • Process Synchronization: State information helps coordinate process interactions

⚡ Preemption and Non-Preemption

State transitions can be:

Preemptive

The operating system can forcibly move a process from running to ready state (e.g., when a higher priority process becomes ready).

Non-Preemptive

The process voluntarily gives up the CPU (e.g., when it finishes its time slice or needs to wait for I/O).

📝 Summary

Process states and their transitions form the foundation of process management in operating systems. Understanding these states helps in:

  • Designing efficient scheduling algorithms
  • Optimizing resource utilization
  • Implementing process synchronization mechanisms
  • Debugging process-related issues
