📡 Inter-Process Communication (IPC)

🕐 2026-02-20 👨‍💻 @rafaelsantos
📚 About: Inter-Process Communication (IPC) refers to mechanisms that allow processes to communicate and synchronize with each other. This topic covers pipes, FIFOs, message queues, shared memory, semaphores, signals, and sockets.

🟢 📚 What is IPC?

Inter-Process Communication (IPC) is a set of mechanisms that enable processes to exchange data and coordinate their activities. Since processes have separate memory spaces, they cannot directly access each other's memory. IPC provides various methods for processes to communicate.

Why IPC is Needed:
  • Processes have isolated memory spaces
  • Direct memory access between processes is not allowed
  • Processes need to share data and coordinate activities
  • IPC provides safe and controlled communication channels

🟡 📚 Types of IPC Mechanisms

Unix-like systems provide several IPC mechanisms, each with different characteristics:

1. Pipes

Unidirectional communication channel for related processes (parent-child).

2. FIFOs (Named Pipes)

Named pipes that allow communication between unrelated processes.

3. Message Queues

Structured message passing with priorities and type-based filtering.

4. Shared Memory

Fastest IPC method - processes share a common memory region.

5. Semaphores

Synchronization primitives for coordinating access to shared resources.

6. Signals

Asynchronous notifications sent to processes.

7. Sockets

Network-based communication, can be used for local or remote IPC.

🟢 📚 Pipes

A pipe is a unidirectional communication channel that connects the standard output of one process to the standard input of another. Pipes are created using the pipe() system call and are typically used for communication between related processes (parent and child).

Pipe Characteristics:
  • Unidirectional (data flows in one direction)
  • Created with pipe() system call
  • Returns two file descriptors: read end and write end
  • Data is buffered by the kernel
  • Limited capacity (typically 64KB)
  • Only works between related processes (same process tree)

🟢 🛠️ Basic Pipe Example

This example demonstrates communication between parent and child processes using a pipe:

C 
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <string.h>

int main() {
    int fd[2];  // fd[0] = read end, fd[1] = write end
    pid_t pid;
    char buffer[100];
    const char *message = "Hello from parent!";
    
    // Create pipe
    if (pipe(fd) == -1) {
        perror("pipe");
        return 1;
    }
    
    // Fork child process
    pid = fork();
    
    if (pid == 0) {
        // Child process - reads from pipe
        close(fd[1]);  // Close write end (child doesn't write)
        
        read(fd[0], buffer, sizeof(buffer));
        printf("Child received: %s\n", buffer);
        
        close(fd[0]);
    } else if (pid > 0) {
        // Parent process - writes to pipe
        close(fd[0]);  // Close read end (parent doesn't read)
        
        write(fd[1], message, strlen(message) + 1);
        printf("Parent sent: %s\n", message);
        
        close(fd[1]);
        wait(NULL);  // Wait for child
    } else {
        perror("fork");
        return 1;
    }
    
    return 0;
}

Code Breakdown

Creating a Pipe

C 
int fd[2];
if (pipe(fd) == -1) {
    perror("pipe");
    return 1;
}

pipe(fd) creates a pipe and stores two file descriptors in the array: fd[0] is the read end, and fd[1] is the write end. If pipe() fails, it returns -1.

Closing Unused Ends

C 
// In child: close write end
close(fd[1]);

// In parent: close read end
close(fd[0]);

Each process should close the file descriptor it doesn't use. This ensures that when one process finishes, the other process will receive EOF (end-of-file) when reading, allowing proper synchronization.

🟡 📚 FIFOs (Named Pipes)

A FIFO (First In, First Out), also called a named pipe, is similar to a regular pipe but has a name in the file system. This allows unrelated processes to communicate.

FIFO Characteristics:
  • Has a name in the file system (created with mkfifo())
  • Can be used by unrelated processes
  • Unidirectional like regular pipes
  • Persists until explicitly removed
  • Blocking I/O by default

🟡 🛠️ FIFO Example

This example demonstrates communication using a named pipe:

C 
#include <stdio.h>
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

int main() {
    const char *fifo_path = "/tmp/myfifo";
    int fd;
    char buffer[100];
    
    // Create FIFO (named pipe)
    if (mkfifo(fifo_path, 0666) == -1) {
        perror("mkfifo");
        // If FIFO already exists, that's okay
        if (errno != EEXIST) {
            return 1;
        }
    }
    
    // Open FIFO for writing
    fd = open(fifo_path, O_WRONLY);
    if (fd == -1) {
        perror("open");
        return 1;
    }
    
    // Write to FIFO
    const char *message = "Hello from writer!";
    write(fd, message, strlen(message) + 1);
    
    close(fd);
    printf("Writer: Sent message\n");
    
    return 0;
}

🟡 📚 Message Queues

Message queues provide a structured way to send messages between processes. Messages have a type and can be retrieved based on type or in FIFO order.

Message Queue Characteristics:
  • Messages have a type identifier
  • Messages can be retrieved by type or in order
  • Persistent across process termination
  • System-wide resource (identified by key)
  • Limited by system quotas

🟡 🛠️ Message Queue Example

This example demonstrates message queue communication:

C 
#include <stdio.h>
#include <sys/msg.h>
#include <sys/ipc.h>
#include <string.h>

struct msgbuf {
    long mtype;
    char mtext[100];
};

int main() {
    key_t key = ftok("/tmp", 'A');
    int msgid;
    struct msgbuf message;
    
    // Create message queue
    msgid = msgget(key, 0666 | IPC_CREAT);
    if (msgid == -1) {
        perror("msgget");
        return 1;
    }
    
    // Send message
    message.mtype = 1;
    strcpy(message.mtext, "Hello from message queue!");
    
    if (msgsnd(msgid, &message, sizeof(message.mtext), 0) == -1) {
        perror("msgsnd");
        return 1;
    }
    
    printf("Message sent: %s\n", message.mtext);
    
    return 0;
}

🟡 📚 Shared Memory

Shared memory is the fastest IPC mechanism. It allows multiple processes to access the same region of memory, enabling very fast data sharing.

Shared Memory Characteristics:
  • Fastest IPC method (no data copying)
  • Multiple processes can access the same memory
  • Requires synchronization (semaphores, mutexes)
  • System-wide resource (identified by key)
  • Persists until explicitly removed

🟡 🛠️ Shared Memory Example

This example demonstrates shared memory usage:

C 
#include <stdio.h>
#include <sys/shm.h>
#include <sys/ipc.h>
#include <string.h>

int main() {
    key_t key = ftok("/tmp", 'B');
    int shmid;
    char *shm;
    
    // Create shared memory segment
    shmid = shmget(key, 1024, 0666 | IPC_CREAT);
    if (shmid == -1) {
        perror("shmget");
        return 1;
    }
    
    // Attach shared memory
    shm = (char *)shmat(shmid, NULL, 0);
    if (shm == (char *)-1) {
        perror("shmat");
        return 1;
    }
    
    // Write to shared memory
    strcpy(shm, "Hello from shared memory!");
    printf("Written to shared memory: %s\n", shm);
    
    // Detach shared memory
    shmdt(shm);
    
    return 0;
}

🟡 📚 Semaphores

Semaphores are synchronization primitives used to control access to shared resources. They prevent race conditions by ensuring only one process accesses a critical section at a time.

Semaphore Characteristics:
  • Integer counter that tracks available resources
  • Atomic operations: wait (P) and signal (V)
  • Used for mutual exclusion and synchronization
  • Can be binary (0 or 1) or counting
  • System-wide resource (identified by key)

🟡 🛠️ Semaphore Example

This example demonstrates semaphore usage for mutual exclusion:

C 
#include <stdio.h>
#include <sys/sem.h>
#include <sys/ipc.h>
#include <sys/types.h>

union semun {
    int val;
    struct semid_ds *buf;
    unsigned short *array;
};

int main() {
    key_t key = ftok("/tmp", 'C');
    int semid;
    union semun arg;
    struct sembuf sb;
    
    // Create semaphore set
    semid = semget(key, 1, 0666 | IPC_CREAT);
    if (semid == -1) {
        perror("semget");
        return 1;
    }
    
    // Initialize semaphore to 1 (binary semaphore)
    arg.val = 1;
    if (semctl(semid, 0, SETVAL, arg) == -1) {
        perror("semctl");
        return 1;
    }
    
    // Wait (P operation) - decrement semaphore
    sb.sem_num = 0;
    sb.sem_op = -1;  // Decrement by 1
    sb.sem_flg = 0;
    semop(semid, &sb, 1);
    
    printf("Critical section - semaphore acquired\n");
    
    // Critical section code here
    
    // Signal (V operation) - increment semaphore
    sb.sem_op = 1;  // Increment by 1
    semop(semid, &sb, 1);
    
    printf("Critical section - semaphore released\n");
    
    return 0;
}

🟡 📚 Signals

Signals are asynchronous notifications sent to processes. They can be used for IPC, process control, and error handling.

Signal Characteristics:
  • Asynchronous notifications
  • Predefined signal types (SIGINT, SIGTERM, SIGUSR1, etc.)
  • Can be sent by kernel, other processes, or the process itself
  • Process can handle signals with signal handlers
  • Limited information (just signal number)

🟡 🛠️ Signal Example

This example demonstrates signal handling:

C 
#include <stdio.h>
#include <signal.h>
#include <unistd.h>
#include <sys/types.h>

void signal_handler(int sig) {
    printf("Received signal %d\n", sig);
}

int main() {
    pid_t pid;
    
    // Set up signal handler
    signal(SIGUSR1, signal_handler);
    
    pid = fork();
    
    if (pid == 0) {
        // Child process
        printf("Child: Waiting for signal...\n");
        pause();  // Wait for signal
        printf("Child: Signal received!\n");
    } else if (pid > 0) {
        // Parent process
        sleep(1);  // Give child time to set up handler
        printf("Parent: Sending SIGUSR1 to child\n");
        kill(pid, SIGUSR1);
        wait(NULL);
    } else {
        perror("fork");
        return 1;
    }
    
    return 0;
}

🟡 📚 Sockets

Sockets provide network-based communication. They can be used for local IPC (Unix domain sockets) or remote communication (Internet sockets).

Socket Characteristics:
  • Can be used for local or remote communication
  • Unix domain sockets for local IPC (faster than network sockets)
  • Internet sockets for network communication
  • Bidirectional communication
  • Supports multiple protocols (TCP, UDP)

🟡 🛠️ Unix Domain Socket Example

This example demonstrates local IPC using Unix domain sockets:

C 
#include <stdio.h>
#include <sys/socket.h>
#include <sys/un.h>
#include <unistd.h>
#include <string.h>

int main() {
    int sockfd;
    struct sockaddr_un addr;
    const char *socket_path = "/tmp/mysocket";
    char buffer[100];
    
    // Create socket
    sockfd = socket(AF_UNIX, SOCK_STREAM, 0);
    if (sockfd == -1) {
        perror("socket");
        return 1;
    }
    
    // Set up address
    memset(&addr, 0, sizeof(addr));
    addr.sun_family = AF_UNIX;
    strncpy(addr.sun_path, socket_path, sizeof(addr.sun_path) - 1);
    
    // Bind socket
    if (bind(sockfd, (struct sockaddr *)&addr, sizeof(addr)) == -1) {
        perror("bind");
        close(sockfd);
        return 1;
    }
    
    // Listen for connections
    if (listen(sockfd, 5) == -1) {
        perror("listen");
        close(sockfd);
        return 1;
    }
    
    printf("Server: Listening on %s\n", socket_path);
    
    // Accept connection
    int client_fd = accept(sockfd, NULL, NULL);
    if (client_fd == -1) {
        perror("accept");
        close(sockfd);
        return 1;
    }
    
    // Receive message
    read(client_fd, buffer, sizeof(buffer));
    printf("Server: Received: %s\n", buffer);
    
    close(client_fd);
    close(sockfd);
    unlink(socket_path);  // Remove socket file
    
    return 0;
}

🔴 📚 IPC Mechanism Comparison

Different IPC mechanisms have different characteristics. Here's a comparison:

Mechanism Speed Complexity Use Case
Shared Memory Fastest High (needs synchronization) High-performance data sharing
Sockets Fast (Unix domain) Medium Network or local communication
Message Queues Medium Medium Structured message passing
Pipes/FIFOs Medium Low Simple unidirectional communication
Signals Fast Low Asynchronous notifications

🔴 📚 Best Practices for IPC

When choosing and using IPC mechanisms:

Best Practices:
  • Choose the right mechanism: Use shared memory for high-performance, pipes for simplicity, sockets for network communication
  • Synchronize properly: Use semaphores or mutexes with shared memory
  • Handle errors: Always check return values and handle errors appropriately
  • Clean up resources: Remove IPC objects (message queues, shared memory, semaphores) when done
  • Use timeouts: Avoid indefinite blocking by using non-blocking I/O or timeouts
  • Consider security: Set appropriate permissions on IPC objects
