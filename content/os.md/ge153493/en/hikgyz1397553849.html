🧵 Thread Concepts

🕐 2025-02-20 09:40:00 👨‍💻 @rafaelsantos
📚 About: Threads are lightweight processes that share the same memory space and resources within a process. They enable concurrent execution within a single process, improving application responsiveness and resource utilization. Understanding thread concepts is essential for developing efficient multi-threaded applications.

🟢 📚 What is a Thread?

A thread is the smallest unit of execution within a process. Unlike processes, which have separate memory spaces, threads within the same process share memory, file descriptors, and other resources. This makes threads more efficient for concurrent operations within a single application.

Key characteristics of threads:

  • Lightweight: Threads require less overhead than processes
  • Shared memory: All threads in a process share the same address space
  • Independent execution: Each thread has its own program counter, stack, and registers
  • Faster context switching: Switching between threads is faster than switching between processes

🟢 📚 Thread vs Process

Understanding the differences between threads and processes is crucial for choosing the right concurrency model for your application.

Process:
  • Has its own memory space (isolated)
  • Heavyweight - requires more system resources
  • Slower to create and destroy
  • Slower context switching
  • Inter-process communication (IPC) required for sharing data
  • More secure - process isolation prevents interference
Thread:
  • Shares memory space with other threads in the same process
  • Lightweight - requires fewer system resources
  • Faster to create and destroy
  • Faster context switching
  • Direct memory access for sharing data
  • Less secure - requires synchronization to prevent race conditions

🟡 📚 Thread Lifecycle

Threads go through various states during their lifetime. The thread lifecycle consists of several distinct states:

  • New: Thread object is created but not yet started
  • Runnable/Ready: Thread is ready to run and waiting for CPU time
  • Running: Thread is currently executing on the CPU
  • Blocked/Waiting: Thread is waiting for a resource or event (I/O, lock, etc.)
  • Terminated: Thread has completed execution or been terminated

🟡 📚 Thread Models

Operating systems implement different thread models that determine how threads are managed and scheduled. The main thread models are:

Many-to-One Model (User-Level Threads)

Multiple user threads are mapped to a single kernel thread. The thread library manages all thread operations in user space, making it very efficient. However, if one thread blocks, all threads in the process block.

Advantages:
  • Fast thread creation and switching
  • No kernel involvement needed
  • Portable across different operating systems
Disadvantages:
  • Cannot take advantage of multiple CPUs
  • If one thread blocks, all threads block
  • Limited scalability

One-to-One Model (Kernel-Level Threads)

Each user thread is mapped to a separate kernel thread. The operating system kernel manages thread creation, scheduling, and synchronization. This model provides true parallelism on multi-core systems.

Advantages:
  • True parallelism on multi-core systems
  • If one thread blocks, others can continue
  • Better for CPU-intensive tasks
Disadvantages:
  • More overhead for thread creation
  • Requires kernel involvement
  • Limited number of threads (system resource constraints)

Many-to-Many Model (Hybrid Threads)

Multiple user threads are mapped to a smaller or equal number of kernel threads. This model combines the benefits of both user-level and kernel-level threads, providing flexibility and efficiency.

Advantages:
  • Can create many user threads
  • True parallelism on multi-core systems
  • Flexible thread management
Disadvantages:
  • More complex implementation
  • Requires coordination between user and kernel levels

🟡 📚 User Threads

User threads (also called user-level threads) are managed entirely by a thread library in user space, without kernel support. The operating system sees only the process, not the individual threads.

Characteristics of user threads:

  • Fast creation: No system call required
  • Fast context switching: No kernel mode switch needed
  • Custom scheduling: Application can implement its own scheduling algorithm
  • Portability: Can run on any operating system
  • Blocking issue: If one thread blocks, all threads in the process block

🟡 📚 Kernel Threads

Kernel threads are managed directly by the operating system kernel. Each kernel thread is a schedulable entity that the OS can assign to different CPUs.

Characteristics of kernel threads:

  • True parallelism: Can run simultaneously on multiple CPUs
  • Independent blocking: If one thread blocks, others can continue
  • System call overhead: Thread operations require kernel mode switches
  • OS-dependent: Implementation varies by operating system
  • Resource limits: Limited by system resources and OS policies

🟡 🛠️ Thread Creation Example

Here's a simple example of creating and managing threads in a programming language:

C 
#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

void* thread_function(void* arg) {
    int thread_id = *(int*)arg;
    printf("Thread %d is running\n", thread_id);
    sleep(2);
    printf("Thread %d is finished\n", thread_id);
    return NULL;
}

int main() {
    pthread_t threads[3];
    int thread_ids[3];
    
    // Create three threads
    for (int i = 0; i < 3; i++) {
        thread_ids[i] = i + 1;
        if (pthread_create(&threads[i], NULL, thread_function, &thread_ids[i]) != 0) {
            fprintf(stderr, "Error creating thread %d\n", i + 1);
            return 1;
        }
    }
    
    // Wait for all threads to complete
    for (int i = 0; i < 3; i++) {
        pthread_join(threads[i], NULL);
    }
    
    printf("All threads completed\n");
    return 0;
}

Code Breakdown

Thread Function

C 
void* thread_function(void* arg) {
    int thread_id = *(int*)arg;
    printf("Thread %d is running\n", thread_id);
    sleep(2);
    printf("Thread %d is finished\n", thread_id);
    return NULL;
}

This is the function that each thread will execute. It receives a pointer to an integer (thread ID), prints a message, sleeps for 2 seconds, and then prints a completion message. The function signature `void* thread_function(void* arg)` is required by the POSIX threads (pthread) library.

Thread Creation

C 
pthread_t threads[3];
int thread_ids[3];

for (int i = 0; i < 3; i++) {
    thread_ids[i] = i + 1;
    if (pthread_create(&threads[i], NULL, thread_function, &thread_ids[i]) != 0) {
        fprintf(stderr, "Error creating thread %d\n", i + 1);
        return 1;
    }
}

The `pthread_create()` function creates a new thread. It takes four parameters: a pointer to a `pthread_t` variable to store the thread ID, thread attributes (NULL for defaults), the function to execute, and an argument to pass to that function. If creation fails, the function returns a non-zero value.

Thread Joining

C 
for (int i = 0; i < 3; i++) {
    pthread_join(threads[i], NULL);
}

The `pthread_join()` function waits for a thread to complete execution. It blocks the calling thread until the specified thread terminates. The second parameter (NULL here) is used to retrieve the thread's return value if needed. This ensures that the main thread waits for all worker threads to finish before proceeding.

🔴 📚 Thread Synchronization

Since threads share memory space, proper synchronization is essential to prevent race conditions and ensure data consistency. Common synchronization mechanisms include:

  • Mutexes: Mutual exclusion locks that allow only one thread to access a critical section
  • Semaphores: Counting semaphores that control access to a pool of resources
  • Condition Variables: Allow threads to wait for specific conditions to be met
  • Barriers: Synchronization points where threads wait until all threads reach the barrier
  • Read-Write Locks: Allow multiple readers or a single writer

🔴 📚 Thread Safety

Thread safety refers to the property of code that functions correctly when accessed by multiple threads simultaneously. Thread-safe code prevents race conditions and ensures data integrity.

Common techniques for achieving thread safety:

  • Immutable objects: Objects that cannot be modified after creation
  • Synchronized methods: Methods that can only be executed by one thread at a time
  • Thread-local storage: Each thread has its own copy of data
  • Atomic operations: Operations that complete without interruption
  • Lock-free data structures: Data structures designed for concurrent access without locks

🔴 📚 Thread Pools

A thread pool is a collection of pre-created threads that are reused to execute tasks. Instead of creating a new thread for each task, tasks are submitted to the pool, and an available thread executes them.

Benefits of thread pools:

  • Reduced overhead: Avoids the cost of creating and destroying threads
  • Better resource management: Limits the number of concurrent threads
  • Improved performance: Threads are ready to execute tasks immediately
  • Controlled concurrency: Prevents system overload from too many threads

📚 Summary

  • Threads are lightweight execution units within a process that share memory space
  • Threads vs Processes: Threads share memory and are faster, while processes are isolated and more secure
  • Thread Lifecycle includes states: New, Runnable, Running, Blocked, and Terminated
  • Thread Models include Many-to-One (user threads), One-to-One (kernel threads), and Many-to-Many (hybrid)
  • User Threads are managed in user space, fast but cannot utilize multiple CPUs
  • Kernel Threads are managed by the OS, support true parallelism but have more overhead
  • Thread Synchronization is essential to prevent race conditions when threads share data
  • Thread Safety ensures code works correctly with concurrent thread access
  • Thread Pools improve performance by reusing threads instead of creating new ones
