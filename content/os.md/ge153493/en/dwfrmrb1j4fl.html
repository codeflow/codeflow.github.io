🔄 Context Switch

🕐 20/02/2026 15:00:00 👨‍💻 @rafaelsantos
📚 About: Context switching is the process of saving the state of a currently running process and restoring the state of another process so it can resume execution. This is a fundamental mechanism in multitasking operating systems that allows multiple processes to share the CPU.

🟢 📚 What is Context Switch?

A context switch is the mechanism by which the operating system saves the execution context (state) of the currently running process and loads the execution context of another process to continue its execution. This allows the CPU to switch between different processes, enabling multitasking and time-sharing.

The execution context includes all the information needed to resume a process exactly where it left off:

  • CPU Registers: Program counter (PC), stack pointer (SP), general-purpose registers, status registers
  • Memory Management: Page tables, memory mappings, virtual address space
  • Process State: Process ID (PID), priority, scheduling information
  • I/O State: Open file descriptors, I/O buffers, device states

🟢 📚 Why Context Switching is Needed

Context switching is essential for:

  • Multitasking: Allowing multiple processes to run concurrently on a single CPU
  • Time-Sharing: Fairly distributing CPU time among multiple processes
  • Preemptive Scheduling: Interrupting running processes to give CPU time to higher-priority processes
  • I/O Operations: Switching to another process when the current one is waiting for I/O
  • Responsiveness: Ensuring the system remains responsive to user interactions

🟡 📚 Context Switch Process

The context switch process involves several steps:

1. Save Current Process State

When a context switch is triggered (by a timer interrupt, I/O completion, or system call), the operating system:

  • Saves all CPU registers to the Process Control Block (PCB) of the current process
  • Updates the process state (e.g., from "running" to "ready" or "waiting")
  • Stores the program counter to know where to resume execution
  • Saves stack pointer and other register values

2. Select Next Process

The scheduler selects the next process to run based on the scheduling algorithm:

  • Checks the ready queue for processes waiting to execute
  • Applies scheduling criteria (priority, time quantum, etc.)
  • Selects the most appropriate process

3. Restore Next Process State

The operating system loads the saved state of the selected process:

  • Restores all CPU registers from the PCB
  • Updates memory management unit (MMU) with the process's page tables
  • Restores the program counter to resume execution
  • Updates process state to "running"

4. Resume Execution

The CPU begins executing the newly loaded process from where it was previously interrupted.

🟡 📚 Context Switch Overhead

Context switching has performance overhead because it requires:

  • CPU Time: Time spent saving and restoring process state
  • Cache Flushing: CPU caches may need to be flushed or invalidated
  • TLB Flush: Translation Lookaside Buffer (TLB) may need to be cleared
  • Memory Access: Reading from and writing to memory (PCB storage)

Typical context switch times range from:

  • Microseconds: On modern systems (1-10 microseconds)
  • Milliseconds: On older or slower systems

The overhead depends on:

  • Number of registers to save/restore
  • Memory access speed
  • Cache efficiency
  • Hardware support for context switching

🟡 🛠️ Context Switch Between Processes vs Threads

Context switching behavior differs between processes and threads:

Process Context Switch

Switching between processes (different address spaces):

  • More Expensive: Requires changing memory address space
  • MMU Update: Must update page tables and TLB
  • Full State Save: All registers, memory mappings, file descriptors
  • Cache Impact: Higher chance of cache misses

Thread Context Switch

Switching between threads (same address space):

  • Less Expensive: No memory address space change
  • No MMU Update: Page tables remain the same
  • Minimal State Save: Only CPU registers and stack pointer
  • Better Cache Performance: Shared memory space improves cache hit rate

🟡 🛠️ Context Switch Implementation Example

The following example demonstrates a simplified context switch implementation:

C 
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// Process Control Block (PCB)
typedef struct {
    int pid;
    int state;  // 0: ready, 1: running, 2: waiting
    void* stack_pointer;
    int program_counter;
    int registers[8];  // General-purpose registers
} PCB;

// Global variables
PCB* current_process = NULL;
PCB* ready_queue[10];
int ready_count = 0;

// Save current process context
void save_context(PCB* pcb) {
    // In real implementation, this would use assembly to save registers
    // For demonstration, we simulate saving state
    printf("Saving context for process %d\n", pcb->pid);
    printf("  - Program Counter: %d\n", pcb->program_counter);
    printf("  - Stack Pointer: %p\n", pcb->stack_pointer);
    printf("  - State: %d\n", pcb->state);
}

// Restore process context
void restore_context(PCB* pcb) {
    // In real implementation, this would use assembly to restore registers
    // For demonstration, we simulate restoring state
    printf("Restoring context for process %d\n", pcb->pid);
    printf("  - Program Counter: %d\n", pcb->program_counter);
    printf("  - Stack Pointer: %p\n", pcb->stack_pointer);
    pcb->state = 1;  // Set to running
}

// Context switch function
void context_switch(PCB* next_process) {
    if (current_process != NULL) {
        // Save current process state
        current_process->state = 0;  // Set to ready
        save_context(current_process);
        
        // Add to ready queue
        ready_queue[ready_count++] = current_process;
    }
    
    // Switch to next process
    current_process = next_process;
    restore_context(current_process);
    
    printf("Context switch completed. Now running process %d\n", current_process->pid);
}

// Example usage
int main() {
    // Create sample processes
    PCB p1 = {1, 0, NULL, 100, {0}};
    PCB p2 = {2, 0, NULL, 200, {0}};
    
    // Initial context switch to process 1
    context_switch(&p1);
    
    // Simulate timer interrupt - switch to process 2
    printf("\n--- Timer interrupt ---\n");
    context_switch(&p2);
    
    // Simulate another interrupt - switch back to process 1
    printf("\n--- Timer interrupt ---\n");
    context_switch(&p1);
    
    return 0;
}

🔴 📚 Hardware Support for Context Switching

Modern processors provide hardware support to optimize context switching:

1. Fast System Calls

Special instructions (e.g., syscall, sysenter) that allow efficient transitions between user mode and kernel mode, reducing the overhead of system calls that may trigger context switches.

2. TLB Management

Translation Lookaside Buffer (TLB) management features:

  • ASID (Address Space ID): Allows TLB entries to be tagged with process IDs, avoiding full TLB flushes
  • TLB Invalidation: Selective invalidation of TLB entries when switching address spaces

3. Register Windows (SPARC)

Some architectures (like SPARC) use register windows to reduce context switch overhead by providing separate register sets for different execution contexts.

4. Hardware Task Switching (x86)

x86 architecture provides Task State Segment (TSS) for hardware-assisted task switching, though modern operating systems typically use software-based context switching for better flexibility.

🔴 📚 Optimizing Context Switch Performance

Operating systems use various techniques to minimize context switch overhead:

1. Lazy TLB Flushing

Instead of flushing the entire TLB on every context switch, the OS can:

  • Use Address Space Identifiers (ASID) to tag TLB entries
  • Only flush TLB entries when necessary (when switching to a different address space)
  • Reduce TLB miss penalties

2. Cache-Aware Scheduling

Scheduling algorithms that consider cache locality:

  • Prefer running processes that were recently on the CPU (warm cache)
  • Reduce cache misses and improve overall performance

3. Kernel Threads

Using kernel threads instead of processes for some operations:

  • Threads share the same address space
  • Context switches between threads are faster
  • Reduced memory management overhead

4. Preemption Granularity

Adjusting how frequently preemption occurs:

  • Too frequent: High context switch overhead
  • Too infrequent: Poor responsiveness
  • Balance based on system workload

📊 Context Switch Performance Metrics

Context switch performance is measured by:

  • Context Switch Time: Time to save one process and restore another
  • Context Switch Rate: Number of context switches per second
  • Overhead Percentage: Percentage of CPU time spent on context switching

📝 Summary

Context switching is a fundamental mechanism in operating systems that enables multitasking and time-sharing. Key points:

  • Context switch saves the state of the current process and restores the state of another process
  • It involves saving/restoring CPU registers, memory management information, and process state
  • Context switching has overhead that affects system performance
  • Thread context switches are faster than process context switches
  • Modern hardware and OS optimizations help reduce context switch overhead
  • Balancing context switch frequency is important for system performance and responsiveness
