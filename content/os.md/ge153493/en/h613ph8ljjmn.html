⏱️ Scheduling

🕐 19/02/2026 19:43:21 👨‍💻 @rafaelsantos
📚 About: CPU scheduling is the process of selecting which process should run next on the CPU. Scheduling algorithms determine how processes are allocated CPU time, affecting system performance, response time, and resource utilization.

🟢 📚 What is CPU Scheduling?

CPU scheduling is a fundamental function of the operating system that decides which process in the ready queue should be executed next by the CPU. When multiple processes are ready to run, the scheduler must choose one based on a scheduling algorithm.

The main goals of CPU scheduling are:

  • Maximize CPU utilization: Keep the CPU busy as much as possible
  • Maximize throughput: Complete as many processes as possible per unit time
  • Minimize turnaround time: Reduce the time from process submission to completion
  • Minimize waiting time: Reduce the time processes spend waiting in the ready queue
  • Minimize response time: Reduce the time from request submission to first response

🟢 📚 Scheduling Criteria

Different scheduling algorithms optimize for different criteria:

  • CPU Utilization: Percentage of time the CPU is busy
  • Throughput: Number of processes completed per unit time
  • Turnaround Time: Time from submission to completion (waiting + execution)
  • Waiting Time: Total time spent waiting in the ready queue
  • Response Time: Time from submission to first response (important for interactive systems)

🟡 📚 Preemptive vs Non-Preemptive Scheduling

Scheduling algorithms can be classified based on whether they allow preemption:

Non-Preemptive Scheduling

Once a process is allocated the CPU, it runs until it completes or voluntarily gives up the CPU (e.g., waiting for I/O). The process cannot be interrupted by the scheduler.

  • Advantages: Simple to implement, low overhead, predictable behavior
  • Disadvantages: Poor response time for interactive systems, can lead to starvation
  • Examples: First-Come-First-Served (FCFS), Shortest Job First (SJF) non-preemptive

Preemptive Scheduling

The scheduler can interrupt a running process and allocate the CPU to another process. This allows the system to respond quickly to high-priority processes or time-critical events.

  • Advantages: Better response time, prevents starvation, suitable for time-sharing systems
  • Disadvantages: More complex, higher overhead due to context switching
  • Examples: Round-Robin (RR), Shortest Remaining Time First (SRTF), Priority preemptive

🟡 📚 Scheduling Algorithms

Different scheduling algorithms use different strategies to select the next process:

1. First-Come-First-Served (FCFS)

Processes are executed in the order they arrive. It's a simple non-preemptive algorithm that uses a FIFO (First-In-First-Out) queue.

  • Type: Non-preemptive
  • Advantages: Simple, fair, easy to implement
  • Disadvantages: Poor average waiting time, convoy effect (short processes wait behind long ones)

Example:

Processes arrive in order: P1 (burst time: 24ms), P2 (burst time: 3ms), P3 (burst time: 3ms)

  • P1 runs for 24ms (waiting: 0ms)
  • P2 runs for 3ms (waiting: 24ms)
  • P3 runs for 3ms (waiting: 27ms)
  • Average waiting time: (0 + 24 + 27) / 3 = 17ms

2. Shortest Job First (SJF)

The process with the shortest burst time is executed first. This minimizes average waiting time.

  • Type: Can be preemptive (SRTF) or non-preemptive
  • Advantages: Optimal for minimizing average waiting time (non-preemptive version)
  • Disadvantages: Requires knowledge of burst times (difficult to predict), can cause starvation of long processes

Example (Non-Preemptive SJF):

Processes: P1 (burst: 6ms), P2 (burst: 8ms), P3 (burst: 7ms), P4 (burst: 3ms)

  • Execution order: P4 (3ms) → P1 (6ms) → P3 (7ms) → P2 (8ms)
  • Average waiting time: (0 + 3 + 9 + 16) / 4 = 7ms

3. Priority Scheduling

Each process is assigned a priority, and the process with the highest priority is executed first. Priorities can be static (fixed) or dynamic (change over time).

  • Type: Can be preemptive or non-preemptive
  • Advantages: Flexible, can prioritize important processes
  • Disadvantages: Can cause starvation of low-priority processes, priority inversion problem

4. Round-Robin (RR)

Each process is assigned a fixed time quantum (time slice). Processes are executed in a circular order, and if a process doesn't complete within its time quantum, it's preempted and moved to the end of the queue.

  • Type: Preemptive
  • Advantages: Fair, good response time, prevents starvation
  • Disadvantages: Performance depends on time quantum size (too small: high overhead, too large: approaches FCFS)

Example:

Processes: P1 (burst: 10ms), P2 (burst: 5ms), P3 (burst: 8ms), Time quantum: 3ms

  • P1: 3ms (remaining: 7ms)
  • P2: 3ms (remaining: 2ms)
  • P3: 3ms (remaining: 5ms)
  • P1: 3ms (remaining: 4ms)
  • P2: 2ms (completed)
  • P3: 3ms (remaining: 2ms)
  • P1: 3ms (remaining: 1ms)
  • P3: 2ms (completed)
  • P1: 1ms (completed)

5. Multilevel Queue (MLQ)

Processes are classified into different queues based on their characteristics (e.g., foreground/background, priority). Each queue has its own scheduling algorithm.

  • Type: Can be preemptive or non-preemptive
  • Advantages: Flexible, can optimize for different process types
  • Disadvantages: Complex, can cause starvation if queues are not properly balanced

6. Multilevel Feedback Queue (MLFQ)

Similar to MLQ, but processes can move between queues based on their behavior. Processes that use too much CPU time are moved to lower-priority queues, while I/O-bound processes may be moved to higher-priority queues.

  • Type: Preemptive
  • Advantages: Adapts to process behavior, balances between response time and throughput
  • Disadvantages: Complex to implement and tune

🟡 🛠️ Scheduling Algorithm Implementation Example

The following complete example demonstrates a simple Round-Robin scheduler implementation:

PYTHON 
class Process:
    def __init__(self, pid, burst_time, arrival_time=0):
        self.pid = pid
        self.burst_time = burst_time
        self.remaining_time = burst_time
        self.arrival_time = arrival_time
        self.waiting_time = 0
        self.turnaround_time = 0
        self.completion_time = 0

def round_robin_scheduler(processes, time_quantum):
    """
    Round-Robin scheduling algorithm implementation.
    
    Args:
        processes: List of Process objects
        time_quantum: Time slice allocated to each process
    
    Returns:
        Dictionary with scheduling results
    """
    ready_queue = processes.copy()
    current_time = 0
    completed_processes = []
    gantt_chart = []
    
    while ready_queue:
        process = ready_queue.pop(0)
        
        # Execute process for time quantum or until completion
        if process.remaining_time <= time_quantum:
            execution_time = process.remaining_time
            process.remaining_time = 0
            process.completion_time = current_time + execution_time
            completed_processes.append(process)
        else:
            execution_time = time_quantum
            process.remaining_time -= time_quantum
            ready_queue.append(process)  # Add back to queue
        
        gantt_chart.append({
            'pid': process.pid,
            'start': current_time,
            'end': current_time + execution_time
        })
        
        current_time += execution_time
    
    # Calculate waiting and turnaround times
    for process in completed_processes:
        process.turnaround_time = process.completion_time - process.arrival_time
        process.waiting_time = process.turnaround_time - process.burst_time
    
    return {
        'processes': completed_processes,
        'gantt_chart': gantt_chart,
        'avg_waiting_time': sum(p.waiting_time for p in completed_processes) / len(completed_processes),
        'avg_turnaround_time': sum(p.turnaround_time for p in completed_processes) / len(completed_processes)
    }

# Example usage
if __name__ == "__main__":
    processes = [
        Process(1, 10, 0),
        Process(2, 5, 0),
        Process(3, 8, 0)
    ]
    
    results = round_robin_scheduler(processes, 3)
    
    print("Process Execution Order:")
    for entry in results['gantt_chart']:
        print(f"P{entry['pid']}: {entry['start']}ms - {entry['end']}ms")
    
    print("\nProcess Details:")
    for process in results['processes']:
        print(f"P{process.pid}: Waiting={process.waiting_time}ms, "
              f"Turnaround={process.turnaround_time}ms")
    
    print(f"\nAverage Waiting Time: {results['avg_waiting_time']:.2f}ms")
    print(f"Average Turnaround Time: {results['avg_turnaround_time']:.2f}ms")

This structure allows the scheduler to manage process state and calculate performance metrics.

This is the core Round-Robin logic. The scheduler takes the first process from the ready queue and executes it for the time quantum. If the process completes within the quantum, it's marked as completed. Otherwise, it's preempted and added back to the end of the queue. This ensures fair CPU allocation and prevents any process from monopolizing the CPU.

After all processes complete, we calculate performance metrics. Turnaround time is the total time from arrival to completion (includes waiting and execution). Waiting time is the turnaround time minus the actual execution time (burst time). These metrics help evaluate the effectiveness of the scheduling algorithm.

🔴 📚 Advanced Scheduling Concepts

Modern operating systems use sophisticated scheduling techniques:

Completely Fair Scheduler (CFS) - Linux

Linux uses the Completely Fair Scheduler, which aims to provide fair CPU time allocation. It uses a red-black tree to track processes and calculates virtual runtime to ensure fairness.

  • Virtual Runtime: Normalized execution time based on process priority
  • Fairness: Ensures all processes get proportional CPU time
  • Dynamic Priority: Adjusts process priority based on behavior

Windows Scheduler

Windows uses a priority-based preemptive scheduler with multiple priority classes and levels. It supports:

  • Priority Classes: Real-time, High, Above Normal, Normal, Below Normal, Idle
  • Priority Levels: 0-31 within each class
  • Dynamic Priority Boost: Temporarily increases priority for interactive processes

Real-Time Scheduling

Real-time systems require deterministic scheduling to meet deadlines:

  • Rate Monotonic Scheduling (RMS): Assigns priorities based on task periods
  • Earliest Deadline First (EDF): Schedules tasks with earliest deadlines first
  • Hard Real-Time: Missing deadlines causes system failure
  • Soft Real-Time: Missing deadlines degrades performance but doesn't cause failure

🟡 🛠️ Checking Scheduling Policy in Linux

The following example shows how to check and modify process scheduling policies in Linux:

BASH 
#!/bin/bash

# Check current scheduling policy and priority
chrt -p <PID>

# View scheduling policies for all processes
ps -eo pid,class,rtprio,ni,cmd | head -20

# Set process to SCHED_FIFO (real-time FIFO) with priority 50
chrt -f -p 50 <PID>

# Set process to SCHED_RR (real-time round-robin) with priority 50
chrt -r -p 50 <PID>

# Set process to SCHED_OTHER (normal scheduling) with nice value -10
chrt -o -p 0 <PID>
nice -n -10 <command>

# View scheduling statistics
cat /proc/<PID>/sched

# Common scheduling classes:
# SCHED_NORMAL (SCHED_OTHER): Default time-sharing scheduling
# SCHED_FIFO: Real-time FIFO (first-in-first-out)
# SCHED_RR: Real-time round-robin
# SCHED_BATCH: Batch processing (lower priority)
# SCHED_IDLE: Idle priority (lowest priority)

Part 1: Checking Current Scheduling Policy

BASH 
# Check current scheduling policy and priority
chrt -p <PID>

The chrt -p command displays the current scheduling policy and priority of a process. This is useful for understanding how a process is currently being scheduled and whether it's using real-time or normal scheduling.

Part 2: Setting Real-Time Scheduling

BASH 
# Set process to SCHED_FIFO (real-time FIFO) with priority 50
chrt -f -p 50 <PID>

# Set process to SCHED_RR (real-time round-robin) with priority 50
chrt -r -p 50 <PID>

Real-time scheduling policies (SCHED_FIFO and SCHED_RR) are used for time-critical processes. SCHED_FIFO uses first-in-first-out scheduling within the same priority, while SCHED_RR uses round-robin with time slices. Both require root privileges and can starve normal processes if not used carefully.

Part 3: Understanding Scheduling Classes

Linux supports multiple scheduling classes:

  • SCHED_NORMAL (SCHED_OTHER): Default time-sharing scheduling used by most processes. Uses CFS (Completely Fair Scheduler) in modern Linux kernels.
  • SCHED_FIFO: Real-time FIFO scheduling. Processes run until they complete or voluntarily yield. Higher priority processes preempt lower priority ones.
  • SCHED_RR: Real-time round-robin scheduling. Similar to SCHED_FIFO but with time slices, allowing fair sharing among processes of the same priority.
  • SCHED_BATCH: Designed for batch jobs. Processes have lower priority and are scheduled less frequently to reduce overhead.
  • SCHED_IDLE: Lowest priority scheduling. Used for background tasks that should only run when the system is idle.

📊 Scheduling Performance Comparison

Different algorithms perform differently based on workload characteristics:

Algorithm Best For Average Waiting Time Response Time
FCFS Simple systems, batch processing High (convoy effect) Poor
SJF (Non-preemptive) Known burst times, batch systems Optimal (minimum) Poor
SRTF (Preemptive SJF) Interactive systems with predictable jobs Very good Good
Round-Robin Time-sharing, interactive systems Moderate (depends on quantum) Excellent
Priority Systems with priority requirements Varies Good (for high priority)
MLFQ Mixed workloads (CPU and I/O bound) Good Excellent

📝 Summary

CPU scheduling is a critical component of operating systems that determines system performance and responsiveness. Key points:

  • Scheduling algorithms balance multiple criteria: CPU utilization, throughput, waiting time, and response time
  • Preemptive scheduling provides better responsiveness but has higher overhead
  • Different algorithms are suited for different workloads (batch, interactive, real-time)
  • Modern operating systems use sophisticated schedulers (CFS, MLFQ) that adapt to process behavior
  • Real-time systems require deterministic scheduling to meet deadlines
