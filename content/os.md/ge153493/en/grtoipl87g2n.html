🟢 📚 What is a Process?

A process is an instance of a program in execution. It is the fundamental unit of work in an operating system. A process includes the program code, its current activity (represented by the program counter), and the associated data (variables, files, etc.).

When a program is loaded into memory and executed, it becomes a process. Multiple instances of the same program can run simultaneously as separate processes, each with its own memory space and execution context.

🟡 📚 Process vs Program

Understanding the difference between a process and a program is fundamental to operating system concepts.

Program:

  • Static Entity: A program is a passive collection of instructions stored on disk
  • No Execution State: It doesn't have a program counter, registers, or variables
  • Persistent: Exists as a file until deleted
  • Single Instance: One program file can be used to create multiple processes

Process:

  • Dynamic Entity: A process is an active instance of a program in execution
  • Has Execution State: Includes program counter, registers, stack, heap, data section
  • Temporary: Exists only while the program is running
  • Multiple Instances: The same program can create multiple processes

Analogy: A program is like a recipe (static instructions), while a process is like cooking (active execution of those instructions).

🟡 📚 Process vs Thread

Both processes and threads are units of execution, but they differ in how they share resources and memory.

Process:

  • Independent Memory Space: Each process has its own address space
  • Heavyweight: More overhead for creation, context switching, and communication
  • Isolated: Processes cannot directly access each other's memory
  • IPC Required: Inter-Process Communication (IPC) needed for data sharing
  • More Secure: Failures in one process don't directly affect others

Thread:

  • Shared Memory Space: Threads within a process share the same address space
  • Lightweight: Less overhead for creation and context switching
  • Shared Resources: Threads can directly access shared memory and variables
  • Fast Communication: Data sharing through shared memory (requires synchronization)
  • Less Secure: A bug in one thread can affect the entire process

When to Use Processes: When you need isolation, security, or when tasks are independent.

When to Use Threads: When tasks need to share data frequently, for parallel computation, or for responsive user interfaces.

🟡 📚 Process Control Block (PCB)

The Process Control Block (PCB), also known as a Task Control Block, is a data structure maintained by the operating system for each process. It contains all the information needed to manage and control a process.

PCB Components:

  • Process Identification:
    • Process ID (PID) - unique identifier
    • Parent Process ID (PPID)
    • User ID (UID) - owner of the process
  • Process State: Current state (running, ready, waiting, etc.)
  • CPU Registers: Saved register values when process is not running
  • Program Counter: Address of next instruction to execute
  • Memory Management:
    • Base and limit registers
    • Page tables
    • Memory allocation information
  • Accounting Information:
    • CPU time used
    • Time limits
    • Account numbers
    • Job or process numbers
  • I/O Status Information:
    • List of I/O devices allocated to the process
    • List of open files
    • Pending I/O requests
  • Scheduling Information:
    • Process priority
    • Scheduling queue pointers
    • Other scheduling parameters

The PCB is created when a process is created and deleted when the process terminates. It is the key data structure that allows the OS to manage multiple processes efficiently.

🟡 📚 Process States

A process goes through various states during its lifetime. The state of a process is defined by the current activity of that process.

Common Process States:

  • New: Process is being created
  • Ready: Process is ready to run and waiting for CPU
  • Running: Process is currently executing on CPU
  • Waiting/Blocked: Process is waiting for some event (I/O completion, signal, etc.)
  • Terminated: Process has finished execution

State Transitions:

  • New → Ready: Process is admitted to the system
  • Ready → Running: Process is selected by scheduler (dispatch)
  • Running → Ready: Process is interrupted (time slice expired, higher priority process)
  • Running → Waiting: Process requests I/O or waits for an event
  • Waiting → Ready: Event occurs (I/O completes, signal received)
  • Running → Terminated: Process finishes or is killed

State Diagram:

The process state transitions form a cycle: New → Ready → Running → (Ready or Waiting) → Terminated. Only one process can be in the Running state per CPU at a time, while many processes can be in Ready or Waiting states.

🟡 📚 Process Attributes

Each process has several attributes that describe its characteristics and behavior:

  • Process ID (PID): Unique identifier assigned by the OS
  • Parent Process ID (PPID): ID of the process that created this process
  • User ID (UID): User who owns the process
  • Group ID (GID): Group the process belongs to
  • Priority: Scheduling priority (higher priority processes run first)
  • Nice Value: Adjustment to priority (Unix/Linux)
  • Working Directory: Current directory for file operations
  • Environment Variables: Variables available to the process
  • File Descriptors: Open files and I/O channels

🟡 📚 Process Hierarchy

Processes form a hierarchical tree structure. When a process creates another process, the creator is called the parent process, and the created process is called the child process.

Characteristics:

  • Tree Structure: Processes form a tree with a root process (usually init or systemd)
  • Inheritance: Child processes inherit certain attributes from parent (environment variables, file descriptors)
  • Process Groups: Related processes can be grouped together
  • Sessions: Collection of process groups (used for terminal control)

Init Process: The first process (PID 1) is created by the kernel at boot time. All other processes are descendants of this process.

🟡 📚 Process Memory Layout

Each process has its own memory address space, which is typically organized into several regions:

Stack (High Memory)
Local variables, function calls, return addresses
Heap
Dynamic memory allocation (malloc, new)
Data Segment
Global and static variables
Code Segment (Low Memory)
Program instructions (read-only)

🟡 📚 Process Context

The process context is the collection of all information needed to resume a process after it has been interrupted. It includes:

  • CPU Context: Register values (program counter, stack pointer, general-purpose registers)
  • Memory Context: Memory layout, page tables, allocated memory regions
  • I/O Context: Open files, network connections, device handles
  • Security Context: User ID, group ID, permissions, capabilities

When a process is interrupted, its context is saved in the PCB. When the process resumes, its context is restored from the PCB. This allows the OS to switch between processes efficiently.

🟡 📚 Process Lifecycle

The lifecycle of a process follows these stages:

  1. Creation: Process is created (fork, exec, spawn)
  2. Ready: Process is loaded into memory and ready to run
  3. Running: Process executes on CPU
  4. Waiting: Process waits for events (I/O, signals, synchronization)
  5. Termination: Process finishes execution or is terminated
  6. Cleanup: Resources are deallocated, PCB is removed

The OS manages this lifecycle, ensuring efficient resource utilization and proper cleanup.
